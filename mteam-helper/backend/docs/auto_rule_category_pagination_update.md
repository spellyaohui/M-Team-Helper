# 自动规则分类匹配与分页搜索更新说明

## 更新概述

本次更新主要修复了自动规则在分类匹配上的兼容性问题，并增强了调度任务中的自动搜索能力。

更新后：

- 规则分类字段支持字符串、JSON 字符串数组、列表等多种存储形式
- 自动规则搜索不再只查询第一页，而是支持按页扫描更多结果
- 调度日志增加页码、累计数量和失败页信息，便于排查问题

## 更新时间

2026-03-08

## 修改文件

### 1. 路由规则匹配

- 位置：`backend/routers/rules.py`
- 修改内容：
  - 新增 `json` 解析逻辑
  - 对 `rule.categories` 做统一清洗
  - 兼容以下分类数据格式：
    - 单个字符串
    - JSON 字符串数组
    - Python 列表
    - `null` 和 `'null'` 这类无效值
  - 分类比较前统一转换为字符串，避免 `int` 和 `str` 混用导致匹配失败

### 2. 自动下载调度任务

- 位置：`backend/services/scheduler.py`
- 修改内容：
  - 新增自动规则搜索分页配置：
    - `AUTO_RULE_SEARCH_PAGE_SIZE = 50`
    - `AUTO_RULE_MAX_PAGES = 5`
  - 自动规则搜索从单页改为分页扫描
  - 搜索请求前统一分类参数类型
  - 增加分页日志，包括每页数量、累计数量、总数和失败页信息

## 解决的问题

### 1. 分类匹配异常

部分规则的 `categories` 字段可能以不同格式保存，例如：

```json
"[401, 419]"
```

或：

```json
[401, 419]
```

旧逻辑直接使用 `torrent.get("category") not in rule.categories` 比较，容易出现以下问题：

- JSON 字符串未被解析
- 分类值类型不同，一个是数字，一个是字符串
- `null` 值混入后导致判断异常

新逻辑会先规范化规则分类，再进行字符串级别比较，保证匹配结果稳定。

### 2. 只搜索第一页导致漏种

旧逻辑每次只调用一次搜索接口，固定读取第一页数据。当符合规则的种子不在第一页时，会被直接漏掉。

新逻辑会在可控范围内继续翻页，直到满足以下任一条件：

- 当前页数量不足一页
- 已达到接口返回的总数
- 达到最大扫描页数
- 搜索接口返回失败

## 行为变化

### 分类匹配行为

- 现在更宽容地兼容历史数据和异常格式
- 不会因为 `1` 和 `"1"` 的类型差异导致分类不匹配

### 自动搜索行为

- 每条规则默认最多扫描 5 页
- 每页默认获取 50 条
- 单次任务最多扫描 250 条候选种子

## 兼容性说明

- 本次更新不涉及数据库结构变更
- 现有规则无需迁移即可生效
- 如果规则分类字段已经是标准列表格式，行为与预期保持一致

## 日志示例

```text
规则 '电影免费规则' 第1页获取 50 个种子，累计 50 个，总数 132
规则 '电影免费规则' 第2页获取 50 个种子，累计 100 个，总数 132
规则 '电影免费规则' 第3页获取 32 个种子，累计 132 个，总数 132
```

如果接口失败，日志会包含具体页码，例如：

```text
规则 '电影免费规则' 搜索种子失败（第2页）: 未知错误
```

## 建议验证项

1. 创建包含分类条件的规则，确认字符串和数字分类都能正确匹配
2. 使用结果较多的分类执行自动搜索，确认会继续翻页而不是停在第一页
3. 观察调度日志，确认分页累计数量与接口总数一致
4. 验证空分类、`null` 分类和异常字符串不会导致规则报错
